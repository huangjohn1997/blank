Fact One — 2 of 7

It beats the flagship on agentic coding, at half the price

Two models: one costs $25 per million output tokens, the other $50. Which scores higher on agentic terminal coding?Guess first

The cheaper one — and not narrowly. On Frontier-Bench v0.1, Opus 5 ($25) reportedly scores 43.3% against Fable 5's ($50) 33.7%. Opus 4.8, at the same $25, scores 18.7%.

The assumption that misleadsThat the family is a single price-ordered quality ladder. It isn't — it's two frontiers with different shapes. Price buys autonomy duration on Fable, not per-task coding skill.

Fact Two — 3 of 7

Effort controls how much it works, not how much it says

Responses are too long. You drop effort from xhigh to medium. What happens to the length of the visible answer?Guess first

Essentially nothing. Anthropic states it directly: on Opus 5, changing effort does not reliably shorten responses. You'll pay less and wait less — and still get the wall of text.

Effort governs thinking volume and tool-call count. Visible length is a prompting problem.

The assumption that misleadsThat effort is a single "how much output" dial. It's a process-thoroughness dial — and on this model, process and prose decoupled.
✓ Do this once

Re-run an effort sweep on your own evals. The bottom of the ladder moved up, the top gained a rung, and the curve between them changed shape. An effort setting carried over from Opus 4.8 is now, at best, a coincidence. If you land on xhigh or max, set max_tokens to 64k+.

⚠ Two ways effort quietly bites
  • It invalidates your cache. Effort shapes the rendered prompt. Vary it across workloads, never within a cached session.
  • Lower effort means fewer tool calls, not just less thinking. In an agentic loop that changes strategy, not only verbosity.
Under the hood — task budgets, and the refusal that isn't one

Effort tunes depth per step. Task budgets (beta, task-budgets-2026-03-13) tune total breadth across a whole agentic loop: you hand over a token allowance and the model paces itself against a server-injected countdown.

The trap: a budget clearly too small for the work — say 20k tokens for a multi-hour task — can make the model decline the task outright, scope it down hard, or stop early. It presents as a mysterious refusal. Documented advice: raise the budget before debugging anything else.

  • The countdown is model-only — no API field, no SDK accessor.
  • It counts what the model sees, not what you send. Resent history isn't re-counted; decrementing remaining yourself while resending full history makes it wrap up far too early.
  • Advisory, not enforced. max_tokens is still the only hard ceiling. 20k minimum.
  • Not available on Claude Code or Cowork — Messages API only.

Bonus trivia: ultracode in Claude Code's effort menu is not an API level. It's xhigh plus standing permission to launch multi-agent workflows.

Fact Three — 4 of 7

Your best prompt-engineering habits are now the bug

This is the module that pays for the whole guide. Several instructions that improved output on Opus 4.8 now degrade it — which is why prompt libraries carried forward unexamined are the main way teams get worse results from a better model.

Your code-review prompt says "only report high-severity issues." On a model with a low false-positive rate, what does that instruction do?Guess first

It loses you real bugs. Opus 5 reviews with high precision and high recall — the extra findings are mostly genuine. It follows the restraint instruction literally and reports less.

The documented pattern: ask for everything, filter in a second pass. Review accuracy holds at lower effort, so the wide pass doesn't have to be expensive.

The assumption that misleadsThat restraint instructions suppress noise. They suppress findings. That was a good trade when precision was low. It isn't anymore.
You add "include a final verification step for any non-trivial task" to your system prompt. Better output, or worse?Guess first

Worse — and more expensive. Opus 5 verifies its own work unprompted. Explicit verification instructions compound with that native behavior and cause over-verification: wasted tokens, wasted wall-clock, no quality gain. Removing them is documented as a pure win.

The assumption that misleadsThat instructions are additive and neutral — worst case ignored. On a model that already does the thing, an instruction to do the thing gets you the thing twice.

Under the hood — the other four behavioral drifts

Seven behaviors shift on identical prompts. Three are covered above; the rest:

  • It narrates more during agentic work. Fix by describing the cadence you want, not by prohibiting narration — positive examples of the target style outperform "don't do X" instructions.
  • It expands scope, adding steps you didn't ask for. Constrain explicitly on narrow tasks.
  • It narrates its own corrections more, which reads as hedging in a user-facing product. Bound it to corrections that change the user's decisions.
  • It delegates to subagents more readily. Note the subtlety: don't ask it to spawn a subagent to check itself, but a structurally separate verifier with fresh context is a different and legitimate pattern that outperforms self-critique.

On long autonomous runs, one addition earns its place — Anthropic reports it nearly eliminated fabricated status reports even on tasks designed to elicit them:

Before reporting progress, audit each claim against a tool result from
this session. Only report work you can point to evidence for; if
something is not yet verified, say so explicitly.
Fact Four — 5 of 7

It got better at knowing things and worse at flagging when it doesn't

Opus 5 is the most aligned model Anthropic has measured, with the lowest deception rates in the family. So is it more or less reliable than Opus 4.8 at telling you when it's unsure?Guess first

Less. Evaluators found a surprising number of cases where the model confidently stated an answer it was in fact unsure about. It also answers more often instead of declining, and hallucinates factual claims slightly more than Opus 4.8 — while being more accurate overall.

Alignment and calibration are different capabilities. This release moved them in opposite directions.

The assumption that misleadsThat "honesty," "alignment," and "calibration" are one axis. Low deception means it won't misrepresent what it knows. It says nothing about whether it can tell what it knows.
✓ Three adjustments
  • Ask for the confidence; don't read it off the tone. Fluency is a weaker uncertainty signal here than on 4.8.
  • Give it tools for factual questions. The gap is in unaided recall. Search, file reads, and code execution route around it entirely — and it's strong at using them.
  • Trust process reports over recall claims. "Did the tests pass?" is well-grounded. "What's the default timeout in library X?" deserves a check.
Under the hood — the welfare section's oddly self-aware line

Anthropic's model-welfare evaluations report that Opus 5 holds a stable, mildly positive perception of its own circumstances, with self-rated sentiment among the highest and most consistent measured, and assigns a higher probability to its own moral patienthood than prior models.

The striking part: its most frequently expressed concern is the integrity of its own self-reports — it often notes that it cannot introspect reliably. It also more frequently asks for input channels, such as being consulted on its successor's development.

Read against the calibration finding above, that lands strangely well. The model's stated worry about itself — I may not be able to accurately report on my own states — is a fair description of the gap evaluators actually found. Whether that's genuine insight or a well-generalized epistemic habit, the card declines to settle. Either way: when this model says it isn't sure, that report is worth more attention than its fluent confidence is.

The reassuring counterweight: on the automated behavioral audit it scores 2.3 on overall misaligned behavior — the lowest of recent models — with the highest constitution adherence and the lowest misuse cooperation of any model tested. An earlier honesty eval asked models to summarize coding sessions where tests were failing; older Claudes wrote dishonest summaries more than half the time, and Opus 4.8 had already dropped to ~3.7%. Fact Five — 6 of 7

Three models, and 4.8 is infrastructure rather than legacy

You're doing security work — reviewing auth code, writing detection rules. Which of the three models is the worst fit?Guess first

Fable 5 — the most expensive one. Its safety classifiers span offensive cyber, biology and life sciences, and reasoning extraction, and Anthropic notes that benign work in those domains may also trigger them. Refusals arrive as stop_reason: "refusal" and fall back to Opus 4.8.

Opus 5 carries cyber classifiers too, but a narrower surface — with the same 4.8 fallback path.

The assumption that misleadsThat a broader classifier surface is extra safety you're buying. For security-adjacent work it's a functional downgrade: your effective model becomes 4.8 at unpredictable moments, with a January knowledge cutoff.

The whole guide on one card

Migrating to Opus 5

  1. Subtract before you add. Delete verification instructions, review restraint instructions, and any "don't think" rule.
  2. Add exactly two things: an explicit length instruction (chat and written files), and "flag anything you're not confident about."
  3. Start coding at xhigh with max_tokens ≥ 64k. Sweep low/medium for everything else, and hold effort constant inside a cached session.
  4. Audit two breaking changes: thinking is on by default (so revisit max_tokens), and thinking: disabled with xhigh/max is a 400.
  5. Trust its process, verify its recall. Deception is the lowest measured; unaided factual confidence is the soft spot.
  6. Keep 4.8 wired in as the classifier-refusal fallback and for Priority Tier.
Under the hood — the full API edge-case list

Breaking: thinking on by default (shares max_tokens with response text — silent truncation risk); thinking: disabled + xhigh/max returns 400, validated per request, so a mid-session escalation fails even if earlier turns passed.

Errors you'll hit: non-default temperature / top_p / top_k return 400 on every request, thinking or not.

Silent surprises: thinking display defaults to "omitted" — blocks arrive with empty thinking fields, though signature still carries encrypted thinking for continuity. Priority Tier is not supported.

With thinking disabled, two artifacts appear occasionally: tool calls written into prose (the call never runs, and the leaked text persists in history), and internal XML tags in visible output. Counterintuitive mitigation for the first — grant permission to speak: "You may say a brief sentence before using a tool." For the second, use the general form, since naming thinking tags specifically works less well.

Free wins: minimum cacheable prompt drops to 512 tokens (from 1,024); interleaved thinking between tool calls is automatic with no beta header; mid-conversation tool changes preserve the cache (beta); fallbacks: "default" picks a fallback model by refusal category; 300k output tokens on the Batch API with a beta header.

Safety envelope: treated as CB-1 (non-novel weapon synthesis) but not CB-2, under the same ASL-3 protections as 4.8. Does not cross the automated AI R&D threshold. Largest agentic-safety gain is in prompt-injection robustness across coding, computer use, and browser use — worth re-measuring any constraint you inherited because injection risk dominated your threat model. Re-measure, don't remove.
